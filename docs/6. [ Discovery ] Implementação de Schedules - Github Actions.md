# 📅 Implementação de Schedules — CI/CD no GitHub Actions

Esta documentação detalha o funcionamento, configuração e boas práticas para executar nossa suíte de testes regressivos automatizados no **GitHub Actions** em horários programados (**Schedules**), garantindo o monitoramento contínuo da qualidade da API e do Frontend.

---

## 🧭 O que são Schedules no GitHub Actions?

Um **Schedule** é um disparador (trigger) que permite executar um pipeline (workflow) do GitHub Actions de forma programada em intervalos regulares, de forma semelhante ao utilitário `cron` do Linux.

### 🎯 Casos de Uso em Qualidade (QA)
1. **Smoke Tests Diários**: Rodar uma suíte rápida todas as manhãs para confirmar que os ambientes de desenvolvimento/produção estão no ar.
2. **Regressão Completa Noturna**: Executar todos os testes E2E mais demorados fora do horário comercial para não ocupar a fila de execução dos desenvolvedores.
3. **Monitoramento de Produção**: Executar testes em intervalos curtos (ex: a cada 1 hora) em sites e APIs públicas para alertar em caso de indisponibilidade ou lentidão.

---

## 🛠️ Configuração do Workflow (`test-pipeline.yml`)

O workflow é escrito em formato **YAML** e deve ser salvo no caminho `.github/workflows/test-pipeline.yml`. Abaixo está a estrutura recomendada para nosso projeto com Robot Framework:

```yaml
name: Regressão e Monitoramento Contínuo

on:
  # Disparo agendado via Cron (Ex: Todos os dias às 06:00 AM UTC / 03:00 AM BRT)
  schedule:
    - cron: '0 6 * * *'
  
  # Permite o disparo manual através da aba "Actions" no GitHub
  workflow_dispatch:

  # Dispara automaticamente a cada novo push ou pull request na branch main
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  run-tests:
    name: Executar Testes em Camadas
    runs-on: ubuntu-latest

    steps:
      - name: 📥 Clonar Repositório
        uses: actions/checkout@v4

      - name: 🐍 Configurar Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.10'
          cache: 'pip'

      - name: 📦 Instalar Dependências do Python
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: 🌐 Inicializar Browser Library (Playwright)
        # Comando obrigatório para instalar os binários do browser controlados pelo Robot
        run: rfbrowser clean-install

      - name: 🧪 Executar Testes Automatizados (API e E2E)
        env:
          # Variável secreta cadastrada nas configurações do repositório
          MARVEL_API_TOKEN: ${{ secrets.MARVEL_API_TOKEN }}
        run: |
          robot -d results tests/

      - name: 📈 Gerar Relatório de Saúde dos Testes (Job Summary)
        # Este script lê o xml de resultados e escreve no step summary do GitHub Actions
        if: always()
        run: |
          python utils/generate_summary.py

      - name: 📊 Publicar Relatório de Testes (Artefato)
        # Salva o relatório gerado pelo Robot mesmo em caso de falhas nos testes
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: robot-framework-results
          path: results/
```

## 🔒 Gerenciamento de Credenciais (GitHub Secrets)

Como nossa API GraphQL da MarvelApp necessita de um token para autenticação, **nunca** devemos commitar o arquivo `.env` ou o token diretamente no código do repositório.

### Como configurar o token no GitHub:
1. No seu repositório no GitHub, acesse a aba **Settings** (Configurações).
2. No menu lateral esquerdo, clique em **Secrets and variables** -> **Actions**.
3. Clique no botão **New repository secret**.
4. Configure os campos:
   * **Name**: `MARVEL_API_TOKEN`
   * **Value**: *Insira o seu token gerado na MarvelApp*
5. Clique em **Add secret**.

O GitHub Actions passará a injetar esse valor de forma segura no pipeline como variável de ambiente sempre que os testes rodarem.

## ⏳ Sintaxe do Cron no GitHub Actions

A sintaxe de agendamento utiliza 5 campos separados por espaço:
```
┌───────────── minuto (0 - 59)
│ ┌─────────── hora (0 - 23)
│ │ ┌───────── dia do mês (1 - 31)
│ │ │ ┌─────── mês (1 - 12)
│ │ │ │ ┌───── dia da semana (0 - 6 / domingo a sábado)
│ │ │ │ │
* * * * *
```

### Exemplos Práticos:
* `*/15 * * * *` -> Executa a cada 15 minutos (Monitoramento intensivo).
* `0 8 * * 1-5` -> Executa às 08:00 AM UTC, de segunda a sexta-feira.
* `0 0 * * 0` -> Executa à meia-noite de todo domingo (Regressão geral semanal).

> ⚠️ **Aviso Importante**: O GitHub Actions pode atrasar a execução de workflows agendados em alguns minutos dependendo do tráfego nos servidores gratuitos do GitHub.

## 📊 Geração do Relatório de Saúde (Job Summary)

Assim como demonstrado no exemplo de monitoramento do projeto, adicionamos a geração automática de um **Relatório de Saúde dos Testes (Job Summary)** dinâmico diretamente na página de resumo do GitHub Actions. Isso permite visualização rápida do estado de saúde dos testes sem abrir logs extensos.

### Como funciona?
1. O Robot Framework executa os testes e gera o arquivo estruturado XML (`results/output.xml`).
2. Um script em Python (`.github/workflows/generate_summary.py`) lê esse XML.
3. O script analisa a quantidade de testes passados, falhados e ignorados, e escreve um resumo formatado em Markdown no caminho apontado pela variável de ambiente `$GITHUB_STEP_SUMMARY`.
4. O GitHub Actions renderiza esse Markdown automaticamente no sumário da execução.

### Script de Análise (`utils/generate_summary.py`)
O script foi escrito utilizando apenas a biblioteca padrão do Python (`xml.etree.ElementTree` e `os`), garantindo execução limpa e rápida na esteira de CI/CD:

```python
import xml.etree.ElementTree as ET
import os

def generate_summary():
    xml_file = 'results/output.xml'
    if not os.path.exists(xml_file):
        return
        
    tree = ET.parse(xml_file)
    root = tree.getroot()
    total_stat = root.find('.//statistics/total/stat')
    
    passed = int(total_stat.attrib.get('pass', 0))
    failed = int(total_stat.attrib.get('fail', 0))
    skip = int(total_stat.attrib.get('skip', 0))
    total = passed + failed + skip
    
    pass_rate = (passed / (passed + failed) * 100) if (passed + failed) > 0 else 0
    
    summary_file = os.environ.get('GITHUB_STEP_SUMMARY')
    with open(summary_file, 'a', encoding='utf-8') as f:
        f.write("## 🧪 Relatório de Saúde da Pipeline de Testes\\n\\n")
        if failed == 0:
            f.write("> ### 🟢 STATUS: SUCESSO\\n")
            f.write("> Todos os testes críticos executaram e passaram com sucesso.\\n\\n")
        else:
            f.write(f"> ### 🔴 STATUS: FALHA ({failed} falhas)\\n")
            f.write("> Atenção! Alguns testes falharam no pipeline.\\n\\n")
            
        f.write("### 📊 Métricas de Execução\\n\\n")
        f.write("| Dimensão | Métrica | Valor |\\n")
        f.write("| --- | --- | --- |\\n")
        f.write(f"| 📋 **Total** | Casos de teste | {total} |\\n")
        f.write(f"| ✅ **Sucesso** | Testes passados | {passed} ({pass_rate:.1f}%) |\\n")
        f.write(f"| ❌ **Falhas** | Testes falhados | {failed} |\\n")
```
